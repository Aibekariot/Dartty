# Dartty: задание для Claude

Dartty — маскот-компаньон для рабочего стола Windows. Он живёт поверх всех окон, гуляет по панели задач, садится на края окон и реагирует на работу пользователя. Пользователь — Flutter-разработчик, в разговоре предпочитает русский язык.

Рабочая версия уже есть на Go: `reference/go/`. Она проверена симуляцией. **Задача — переписать её на чистом Dart с тем же поведением, заменить персонажа на новый образ и сделать анимацию плавной.** Когда Dart-версия заработает, папку `reference/` нужно удалить. Она уже в `.gitignore` и в историю git попасть не должна.

## Жёсткие правила

- **Только Dart SDK.** Можно `dart:ffi`, `dart:io`, `dart:convert`, `dart:math`, `dart:typed_data`, `dart:async`. Никаких пакетов в `dependencies`; в `dev_dependencies` допустим только `lints`. Win32 вызывается через собственные FFI-привязки, как в `reference/go/win.go`. Хелперы для строк UTF-16 и выделения памяти нужно написать самим: `package:ffi` не используем.
- **Цель:** Windows 10/11 x64, сборка через `dart compile exe`.
- **Один .exe без консольного окна.** Картинки встраиваются в код (см. «Сборка»).
- **Совместимость настроек.** Файл `%APPDATA%\Dartty\settings.json` должен иметь те же ключи, что в `reference/go/settings.go`. Тогда опыт и уровень пользователя сохранятся при переходе с Go-версии.
- **Перед тем как сказать «готово»:** `dart analyze` проходит без ошибок, симуляция `dart run tool/sim.dart` проходит, `build.bat` собирает exe, exe запускается. Ошибки смотреть в `%APPDATA%\Dartty\dartty.log`. Как Dartty выглядит на экране, ты не видишь, поэтому спрашивай у пользователя или проси скриншот.

## Предлагаемая структура

```
pubspec.yaml               # name: dartty, sdk: ^3.5.0, без зависимостей
bin/dartty.dart            # точка входа: main()
lib/src/app.dart           # «мозг»: состояние, физика, эмоции, таймеры (без Win32!)
lib/src/world.dart         # абстракция World (как interface World в app.go)
lib/src/anim.dart          # плавная анимация (см. ниже)
lib/src/gfx.dart           # картинки premultiplied BGRA, ресайз, рисование
lib/src/png.dart           # мини-декодер PNG (RGBA 8 бит, через ZLibCodec из dart:io)
lib/src/content.dart       # реплики, советы, титулы, списки программ
lib/src/settings.dart
lib/src/win/               # FFI-привязки Win32 и реализация World для Windows
lib/src/assets_data.dart   # СГЕНЕРИРОВАННЫЙ файл с картинками (в .gitignore)
tool/embed_assets.dart     # assets/ → lib/src/assets_data.dart (base64 → Uint8List)
tool/patch_subsystem.dart  # переключает exe с консольного режима на оконный
tool/sim.dart              # симуляция поведения на фальшивом рабочем столе (любая ОС)
build.bat                  # embed → analyze → compile exe → patch → build/Dartty.exe
```

## Как перенести с Go (что важно для Dart)

1. **`app.go` и `gfx.go` переносятся почти построчно.** Они не зависят от Windows. Все тестовые сценарии из `sim_test.go` должны быть в `tool/sim.dart`: появление и приветствие, перетаскивание и приземление на окно, езда вместе с окном, падение, бой с Багом (победа и проигрыш), помодоро, совет дня, 6 часов «жизни» без выхода за экран.
2. **Цикл сообщений и асинхронность (решено 2026-10-21, не возвращать `await` в GUI).** Изначально предлагалась схема `PeekMessageW` → кадр → `await Future.delayed(...)`. Проверка показала, что она ненадёжна: после `await` Dart VM может продолжить изолят на другом потоке ОС из пула (под нагрузкой с изолятами, HTTP и сборкой мусора за один прогон было 3–4 потока), а окна Win32 получают сообщения только в потоке-создателе. Поэтому сделано так (`lib/src/win/runner.dart`):
   - GUI-поток крутит синхронный цикл `PeekMessageW(PM_REMOVE)` → кадр → `MsgWaitForMultipleObjectsEx` до следующего кадра (просыпается и раньше, на ввод) и никогда не отдаёт управление event loop. Сон на таймере высокого разрешения `CreateWaitableTimerExW(CREATE_WAITABLE_TIMER_HIGH_RESOLUTION)`: в Windows 11 `timeBeginPeriod(1)` может не действовать. Раз в 2 с кадр сверяет `GetCurrentThreadId` и пишет в журнал, если поток сменился.
   - Внутри модальных циклов Windows (`TrackPopupMenu`) Dart-код не крутится, поэтому есть ещё `SetTimer` (WM_TIMER, 16 мс): кадр рисуется из оконной процедуры, если обычный цикл стоит дольше 25 мс.
   - Всё асинхронное (будущий HTTP к локальному ИИ через `HttpClient`) живёт в фоновом изоляте `lib/src/win/worker.dart` со своим event loop. GUI шлёт задачу через `SendPort`, ответ приходит в окно управления через `PostMessageW` (`WM_APP+3`, lParam — указатель на ответ в HeapAlloc). Изолят запускается до создания окон: это единственный `await` в программе. При старте мост проверяется запросом `ping`.
3. **Колбэки.** Для WndProc и EnumWindows используй `NativeCallable.isolateLocal`. Они вызываются синхронно в том же потоке.
4. **Слоистые окна.** `UpdateLayeredWindow` + 32-битный DIB с premultiplied BGRA, всё как в `main_windows.go`: три окна (Dartty, облачко, Баг) и скрытое окно для трея и меню.
5. **Текст в облачке.** GDI `DrawTextW` белым по чёрному в DIB, яркость пикселя используется как маска покрытия (см. `RenderText` в Go).
6. **Иконки.** Иконку трея и окна грузи из встроенных байт `.ico` через `LookupIconIdFromDirectoryEx` + `CreateIconFromResourceEx`. Иконку самого exe можно потом поставить через `rcedit`, если он установлен, но это необязательно.

## Новый персонаж: assets/sprites

Все спрайты лежат на холсте **360×312**, лапы на линии **y=304**, по центру по горизонтали. Вокруг персонажа уже нарисовано мягкое синее свечение, чтобы он был виден на тёмных обоях. Подробности в `sprites.json`.

| Файл | Когда показывать |
|---|---|
| `idle` | обычное состояние |
| `idle_blink` | **моргание**: точная копия idle с закрытыми глазами, накладывается без сдвига |
| `excited` | радость, клик, прыжок |
| `pathos` | эпичная поза: колдовство, помодоро-старт, совет |
| `focused` | сидит сосредоточенно: фокус-режим помодоро |
| `curious` | смотрит на курсор (вправо, зеркалить) |
| `sleep` | спит |
| `offended` | обиделся, отвернулся вправо |
| `scared` | испуг, падение, его тащат |
| `angry` | злость, бой с Багом (красное свечение) |
| `sad` | грусть, выход из программы, Баг сбежал |
| `blink` | «довольно зажмурился»: после похвалы. Это отдельная поза, НЕ для моргания |
| `side` | вид сбоку, вправо: стоит, перед тем как пойти |
| `walk_body` + `walk_foot` | **ходьба**: тело без лапок + одна лапка, см. «Анимация» |
| `edge` | сидит на краю окна, лапки свисают. Линия сиденья `seatLine` = y 236 холста ставится на верхний край окна |
| `wave` | машет: приветствие, «показать Dartty» |
| `yawn` | зевает: перед сном и при напоминании «пора спать» |
| `proud` | гордится: новый уровень, победа над Багом, час кода |
| `bug_idle`, `bug_attack`, `bug_dead` | враг Баг (тот же холст) |

Исходники для перерисовки лежат в `assets/source/`. Пиксельная версия (`pixel_concept.png`) пока не используется: если пользователь пришлёт полный лист пиксельных поз, добавим в меню переключатель стиля.

## Анимация: главное улучшение

В Go-версии ходьба дёрганая: две картинки сменялись 4 раза в секунду, а окно двигалось целыми пикселями при 30 fps. Нужно:

1. **60 fps**, позиция во float. Дробную часть координаты рисуй внутри холста (билинейно), а окно двигай на целую часть. Так движение без рывков по пикселям.
2. **Походка вперевалку, как у пингвина**, из `walk_body` и `walk_foot`:
   - фаза шага φ растёт пропорционально пройденному расстоянию, а не времени, чтобы лапки не «скользили»;
   - тело покачивается: поворот вокруг точки между лапками ±4–6°, лёгкий подскок вверх на 2–4 px (на холсте) дважды за цикл, небольшое сжатие в момент касания;
   - две копии лапки: дальняя затемнена примерно до 60% и нарисована ПОЗАДИ тела, ближняя — спереди. Сдвиг по x: `±10·sin(φ)`, подъём `max(0, cos(φ))·5` для ближней и то же со сдвигом фазы π для дальней. Исходная точка лапки — `walk.footOffset` из `sprites.json`;
   - при ходьбе влево всё зеркалится;
   - старт и остановка с плавным разгоном и торможением за 0,2–0,3 с; перед началом ходьбы короткий поворот через `side`.
3. **Плавные переходы между позами:** кроссфейд за 120–180 мс с лёгким «пружинным» масштабом (squash 0,96 → 1,0). Никакой мгновенной смены картинки.
4. **Пружины вместо линейных формул.** Масштаб, наклон и подскок задаются целевым значением, а реальное значение тянется к нему пружиной с затуханием (например, жёсткость 180, демпфирование 14). Приземление: сжатие по высоте до 0,8 и отскок к 1,0 с одним-двумя затухающими колебаниями.
5. **Моргание:** каждые 3–6 с (иногда двойное) на 90–130 мс показывать `idle_blink` поверх `idle`. Только для позы idle.
6. **Дыхание:** очень лёгкое (±1%) масштабирование по высоте от лап, период около 3 с.
7. **Колыхание плаща:** нижнюю треть спрайта сдвигай по x синусоидой. Смещение растёт от 0 у пояса до 2–3 px у подола и сильнее при ходьбе и падении. Это сетка из горизонтальных полос, а не поворот всего спрайта.
8. **Наклон к курсору:** в позе `curious` тело слегка наклоняется (±3°) в сторону курсора.
9. **Прыжки на окна:** присед (squash) 0,12 с → полёт по дуге с растяжением → приземление на `edge` с пружинным сжатием.
10. **Производительность:** перерисовывай холст только при изменении параметров. На ноутбуке пользователя (i5-9300H, встройка + GTX 1650) Dartty в покое не должен занимать больше 1–2% CPU.

## Поведение: перенести 1:1 из reference/go/app.go

- Окно поверх всех, клики проходят сквозь прозрачные пиксели. Перетаскивание и бросок мышкой с гравитацией. Приземление на верхний край окна (при отпускании или падении) и езда вместе с окном. Если окно закрыто, свернуто или перекрыто, Dartty падает.
- Сам гуляет по панели задач и иногда прыгает на края окон.
- Эмоции на клики. На 5 кликов за 2 с злится. Если долго тащить, обижается.
- Засыпает после 5 минут бездействия (ночью раньше), просыпается от ввода. Прячется при полноэкранных играх и видео (`SHQueryUserNotificationState` + проверка, что активное окно на весь монитор).
- Реакции на программы (`content.go`): IDE, терминал, эмулятор, браузер (YouTube, долгий сёрфинг, документация), мессенджеры, Claude.
- Помодоро 25/5/15. После перерыва клик по Dartty запускает новый.
- Напоминания: вода (раз в 45 мин активности), разминка (час), сон (после 23:00).
- Совет дня по Flutter/Dart и совет по запросу из меню.
- Опыт: 1 XP за минуту в IDE/терминале/эмуляторе, +5 за Бага. Уровень L→L+1 стоит 60·L XP, 10 титулов.
- Баг раз в 30–70 мин активности: 7 HP, 10 с, полосы HP и времени. Победа: Баг падает и тает. Проигрыш: убегает за край экрана.
- Облачко над головой: очередь сообщений с приоритетами. Клик по облачку убирает его.
- Трей: меню как в Go (уровень, совет, помодоро, Баг, размер, поведение, напоминания, «не беспокоить», клики сквозь, автозапуск, «Поговорить (скоро)», спрятать, выход). Один экземпляр через мьютекс. Автозапуск через `HKCU\...\Run`.
- Используй новые позы: `wave` при приветствии и показе, `yawn` перед сном и в ночном напоминании, `proud` при новом уровне, победе и часе кода, `edge` на окне.

Персонаж теперь «тёмный маг-звездочёт» в капюшоне, а не лорд в шлеме. **Перепиши фразы, которые прямо цитируют «Звёздные войны»**: «чувствую в тебе силу», «возмущение в Силе», «галактика», «тёмный лорд» и т.п. ## Сборка

`build.bat`:
1. `dart run tool/embed_assets.dart`;
2. `dart analyze`;
3. `dart compile exe bin/dartty.dart -o build/Dartty.exe`;
4. `dart run tool/patch_subsystem.dart build/Dartty.exe`. Он меняет поле Subsystem в PE-заголовке с 3 (console) на 2 (GUI): смещение `e_lfanew` (uint32 по адресу 0x3C) + 4 + 20 + 68, затем проверяет сигнатуру `PE\0\0`.

`.gitignore`: `build/`, `.dart_tool/`, `lib/src/assets_data.dart`, `reference/`.

## Статус на 2026-10-21

Dart-версия написана и работает: `dart analyze` чистый, `dart run tool/sim.dart` проходит (13 сценариев, ~1660 проверок, включая 6 часов жизни), `build.bat` собирает `build\Dartty.exe` (~10 МБ), exe запускается и проходит `--selfcheck`.

Решения, которые стоит знать:
- Цикл сообщений синхронный, асинхронность в фоновом изоляте (см. пункт 2 выше).
- Один экземпляр: сначала `OpenMutexW` и поиск окна `DarttyCtl`, потом свой мьютекс с владением. `GetLastError` после `CreateMutexW` в Dart ненадёжен (VM затирает его между вызовами FFI), из-за этого первая сборка запустилась рядом с Go-версией.
- Облачко и полосы Бага рисуются через функции расстояния (аналитическое сглаживание), а не суперсэмплингом 4×4: в 5 раз быстрее. При сдвиге хвостика перерисовывается только его область поверх готовой основы.
- Позы: на окне `edge` (линия сиденья 236 на верхнем крае окна), перед ходьбой `side`, приветствие и «показать» — `wave`, сон начинается с `yawn`, ночное напоминание — `yawn`, уровень, победа над Багом и час кода — `proud`, клик иногда даёт `blink` (довольно зажмурился).
- Эмоция во время прогулки останавливает ходьбу (в Go Dartty скользил с картинкой эмоции).
- После своего прыжка на окно Dartty не пугается, как при падении (в Go скорость прыжка была 0, теперь она нужна для силы приземления).

Ключи exe: `--selfcheck`, `--stats` (раз в 10 с в журнал: кадры, перерисовки, время, паузы >20 мс), `--no-autostart`.

Замеры (i5-9300H, реальный exe, `--stats`): в покое 60 кадров/с, ~13 перерисовок/с по ~1,1 мс, ~2% одного ядра (~0,25% всего ЦП); при ходьбе ~4–5% ядра.

- Проверка «окно под Dartty закрыто» (`World.rootAt`) не считает окна самого Dartty: в позе `edge` лапки свисают на точку проверки, и раньше Dartty висел в воздухе пару секунд после того, как его окно перекрыли (нашёл пользователь). Теперь Windows-слой ищет окно под Dartty по z-порядку, падение после 3 промахов (~0,36 с). Сценарий `cover` в симуляции.

Где что лежит (с 2026-10-21):
- Проект: `C:\projects_flutter\dartty` (перенесён с рабочего стола в OneDrive по просьбе пользователя).
- Репозиторий: https://github.com/Aibekariot/Dartty, ветка `main`. Он **публичный**, хотя в разделе «Git» выше сказано «приватный»: пользователь выбрал публичный сознательно.
- Установленный exe: `%LOCALAPPDATA%\Programs\Dartty\Dartty.exe`, автозапуск указывает туда. Обновление: выйти из Dartty через трей, `build.bat`, скопировать `build\Dartty.exe` поверх установленного, запустить.

Осталось: пользователь проверяет исправление с перекрытым окном и общую плавность; удалить `reference/` после его подтверждения (она в `.gitignore` и ни в один коммит не попала).
